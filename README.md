# riverbed-psd-gig

Code for **"A Universal Riverbed Sediment Distribution Function Improves Water Security
Assessments"** (Gerasimova et al.).

It fits 25 candidate particle-size distribution functions to riverbed sediment samples,
selects among them by BIC, inverts the fitted distributions for representative grain-size
percentiles, and propagates those into the water-security variables reported in Fig. 5.
Every figure and table in the paper is regenerated by one script here.

  parameters of all 25 functions, and the derived tables.

## Quick start

```bash
conda env create -f environment.yml
conda activate psd-gig

# download the data deposit from its Zenodo DOI, unpack it next to this repository, then:
make inputs                       # copy the deposit's tables into data/
make smoke                        # 3 samples through all 25 functions, ~30 s
make all                          # percentiles -> water metrics -> tables -> figures -> audit
```

`make all` writes tables to `outputs/`, figures to `figures/`, and finishes with
`scripts/audit_numbers.py`, which compares every number the manuscript asserts against what
the pipeline just produced and exits non-zero if any disagree.

## What runs, in order

| Step | Script | Produces |
|---|---|---|
| 0 | `00_fetch_inputs.py` | copies the deposit's tables into `data/` |
| 1 | `01_fit_functions.py` | fitted parameters for the 25 functions (see *Fitting* below) |
| 2 | `02_compute_dvalues.py` | D05–D95 for GIG, Lognormal, Weibull and the best-fit reference |
| 3 | `03_water_metrics.py` | τ\*, Re, Re\*, bedload, critical shear stress, h₁₀₀, Fredle Index; the Fig. 5 matrix |
| 4 | `04_bic_tables.py` | Tables S2–S4, the Fig. 4 summary, and the BIC/RMSE matrices |
| 5 | `05_significance.py` | Table S5 — squared relative errors and paired Wilcoxon tests |
| 6 | `06_rhine_summary.py` | Lower Rhine validation numbers (needs the restricted input, below) |
| 7 | `07_cdf_validity.py` | whether each fitted candidate is actually a valid distribution |
| — | `fig_01.py` … `fig_S05.py` | Figures 1–5 and S1–S5 |
| — | `audit_numbers.py` | every manuscript number vs. the regenerated outputs |
| — | `verify_fits.py` | re-fits a subset and compares against the archived parameters |
| — | `build_data_deposit.py` | assembles the Zenodo deposit |

## Fitting

The 25 candidate functions and their fitting settings are declared in
`src/psd_gig/fit_specs.py`; the closed forms are in `src/psd_gig/function_library.py` and
correspond to Supplementary Table S1.

Two things are worth knowing before you run anything:

**All available sieve grades are used, not only the twelve principal codes.** USGS reports
twelve principal sieve-diameter grades plus 31 additional ones. The archived fits used every
grade present for a sample (up to 43), which is why `configs/fit_usgs.yaml` sets
`size_columns: auto`. Restricting to the twelve principal codes changes the fit for 924 of
the 19,765 samples, by a median of 6.4 BIC units.

**The archived USGS fits are not re-run by default.** They took several days of wall clock at
`maxfev = 1e6` and are shipped in the data deposit. To check that this repository reproduces
them, re-fit a subset:

```bash
make verify                       # 60 samples x GIG / Lognormal / Weibull
python scripts/verify_fits.py --samples 200      # all 25 functions, slower
```

The subset is half random and half drawn from the 924 samples carrying additional sieve
grades, so it exercises the case most sensitive to configuration.

**Nine of the 25 functions are grid-searched** over initial parameter values; the other
sixteen are fitted from a single default guess with one retry. The nine are the ones whose
fits are sensitive to initialisation — the two-parameter functions outside that set are
insensitive (median BIC unchanged to three decimal places under a 50-point grid), while the
three-parameter ones outside it do improve under a grid. See `docs/caveats.md`.

## Lower Rhine

The independent validation samples come from a **CC BY-NC-ND** dataset that we cannot
redistribute. `data/rhine/README.md` explains how to obtain it and what shape the input must
take. Once it is in place:

```bash
make rhine                        # fit, summarise, and draw Fig. S5
```

## Layout

```
configs/     fitting configurations: USGS, Lower Rhine, smoke test
src/psd_gig/ the library -- function definitions, fitting engine, data loaders
scripts/     one numbered script per pipeline stage, plus one per figure
data/        small reference tables (committed) and deposit inputs (fetched, gitignored)
outputs/     everything generated (gitignored)
figures/     final PNG and PDF
docs/        reproduction notes, caveats, and the figure-to-script map
tests/       pytest -- run `make test`
```

## Caveats worth reading before citing a number

`docs/caveats.md` covers the ones that affect interpretation: the channel Reynolds number is
not independent of grain size, the bedload sample selection, percentile estimates that
extrapolate beyond the coarsest sieve, and which candidate functions are valid distributions
at their fitted parameters.
